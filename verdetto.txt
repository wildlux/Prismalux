[CRITICO] WAN server esegue bash -c con payload da nodi remoti
  File:   gui/pages/main_lan_wan.cpp (righe ~3444, ~4123)
  Codice: kind == "shell_cmd" → ProcHelper::run("bash", {"-c", payload}, 20000)
  Rischio: se il token WAN è lasciato vuoto (default consentito dall'UI con
           la scritta "Lascia vuoto = accetta tutti i nodi (NON sicuro)"),
           qualsiasi macchina sulla rete può eseguire comandi arbitrari sul
           sistema host. Nessuna sandbox reale, nessun ulimit attivo.
  Impatto: RCE (Remote Code Execution) — il più grave in lista.
  Fix:    Token WAN obbligatorio + warning rosso visibile se campo vuoto.

[CRITICO] Cloud API key salvata in chiaro in QSettings
  File:   gui/prismalux_paths.h (kCloudApiKey)
          gui/pages/settings_ai.cpp
  Storage: ~/.config/Prismalux/GUI.conf (leggibile da tutti i processi
            con lo stesso UID, incluso malware locale)
  Nota:   Il commento nel codice dice già "spostare in keychain in futuro".
           QKeychain non è installato sul sistema (Not Run nei test).
  Fix:    Installare libqtkeychain-qt6-dev e usare QKeychain per la API key.
           Fallback: file ~/.prismalux/cloud_api.key con chmod 0600.

[IMPORTANTE] TLS LAN disabilitato di default
  File:   gui/lan_server.cpp (righe ~200, ~229)
  Situazione: il codice QSslServer esiste ed è compilato, ma il server
              parte in HTTP semplice sulla LAN. Il token Bearer e il
              confronto timing-safe sono presenti e corretti, ma viaggiano
              in chiaro sulla rete locale.
  Fix:    Abilitare TLS di default; il certificato self-signed viene già
          generato automaticamente via openssl (codice presente a riga ~169).

[NOTA] Costituzione AI aggirabile via prompt crafted
  File:   TOOL_TIP/COSTITUZIONE_PRISMALUX.txt
          gui/ai_client.cpp (3 punti di iniezione)
  Situazione: la costituzione è iniettata nel system prompt ma non è
              enforcement hardware. Un modello fine-tunato o un prompt
              appositamente costruito può ignorarla.
  Valutazione: accettabile per uso personale su sistema locale.
               Da documentare come limite noto.

requirements.txt: 189 righe, 0 versioni pinned (nessun == in tutto il file)

Ogni "pip install -r requirements.txt" può installare versioni diverse.
Se un pacchetto upstream viene compromesso (es. requests, numpy, torch)
o rompe la propria API, l'app si rompe silenziosamente al prossimo install.

Fix:   pip freeze > requirements.lock dopo ogni aggiornamento verificato.
       Usare requirements.lock per i deploy, requirements.txt per lo sviluppo.
